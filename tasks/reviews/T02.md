**Findings:**
- [MAJOR] F1 `app/core/logging.py:83-88`, `app/core/errors.py:61` — every traceback is discarded (`exc_info`, `exc_text`, `stack_info` set to None); unexpected errors log only the exception class. From T07 on, worker/pipeline failures will be undebuggable (no file, line, or call path). Fix: keep a sanitized traceback — frames as `file:line in function` only, no exception message, no source lines, no locals (e.g. build from `traceback.extract_tb`, emit as `stack: [...]`). Keep dropping the exception message. Update `test_exception_content_and_stack_details_are_not_logged` to assert the message is absent but the frame list is present.
- [MAJOR] F2 `tests/conftest.py:155` — `Base.metadata.create_all(connection)` after `alembic upgrade`. Once models exist (T05+), tests will pass even if a migration forgets a table/column/index, hiding broken migrations until deploy. Fix: remove `create_all`; add a test that compares models with the migrated schema (Alembic `compare_metadata` / `alembic check` equivalent) so missing migrations fail CI.
- [MAJOR] F3 `app/core/logging.py:13-34` — substring matching over-redacts and will hide IDs needed for debugging: keys `cv_file_id`, `email_status`, `context` are treated as sensitive; messages like "Processing context: job 42" and "Content-Type: …" are cut to `[REDACTED]`; "Retry in 0.1234567890 seconds" is redacted as a phone. Fix: match sensitive keys exactly or by suffix (`text`, `body`, `content`, `cv_text`, `*_text`, `*_body`, `password`, `*_token`, `*_secret`, `api_key`, `email`, `phone`, `authorization`, `cookie`, …) and never redact keys ending in `_id`, `_status`, `_count`; anchor `ASSIGNMENT_PATTERN` to whole key names; require the phone pattern not to be preceded by `.`/digit. Add tests for these false positives alongside the existing true-positive tests.
- [MINOR] F4 `app/main.py:29`, `app/core/db.py:21`, `app/core/redis.py:10` — `create_app(settings)` only overrides the `get_settings` dependency; `get_engine()` and `get_redis()` still read the global `get_settings()`, so a custom `Settings` passed to `create_app` silently uses a different DB/Redis. Fix: store settings on `app.state` and build engine/Redis from it, or document that `create_app(settings)` only affects request-level settings.
- [MINOR] F5 `app/core/config.py:21` — no guard against the default `SECRET_KEY=change-me` (or a short key) when `APP_ENV=prod`. Add a validator that refuses to start in prod; T04 will sign JWTs with this key.
- [MINOR] F6 `app/core/logging.py:118-119` — `uvicorn.access` is fully disabled, so there is no record of method/status/latency. Suggest a small middleware logging method, route template (not raw path/query), status, duration.
- [MINOR] F7 `tests/conftest.py:140-158` — `hr_ats_test` is reused across runs; editing an existing migration file locally leaves a stale schema. Document "drop `hr_ats_test` after editing a migration" in README, or recreate the test DB once per session.
