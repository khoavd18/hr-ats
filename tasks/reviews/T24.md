**Findings:**
- [MINOR] F1 `backend/app/email/inbound.py:383-389` — a failed size fetch (`result != "OK"` or no `RFC822.SIZE` match) is reported under the status code `IMAP_MESSAGE_TOO_LARGE`, conflating "could not read size" with "oversized". Behaviour is safe (message skipped, left unread), but the admin-facing status code is misleading. Consider a distinct code (e.g. `IMAP_READ_FAILED`) when the size cannot be parsed. Non-blocking.
- [MINOR] F2 `backend/app/email/inbound.py:155-166` / `203-291` — when a done `email`-source CV has no extractable candidate email, `recover_intake`'s `done` subquery (no EmailMessage row exists) re-selects it every poll and calls `queue_receipt`, which returns early each time. Correct and matches the spec ("poll sau thử lại"), but it is unbounded repeated work for CVs that will never get a receipt. Acceptable at current scale; worth a note if inbound volume grows. Non-blocking.

**Human-in-the-loop:** OK. The only auto-send path is `cv_received` with `requires_confirmation=False` under `IMAP_ENABLED`, which the spec explicitly authorizes. `send_email_message` re-checks feature flag, source, done/not-deleted, candidate eligibility, recipient match, template key/active/`requires_confirmation`, and active actor; the `offer`/`disabled`/`deleted`/`changed-email`/`upload` cases are all proven to refuse delivery. No path auto-rejects a candidate or changes a stage.

**Privacy/security:** OK. No message body stored or logged; `caplog` assertions prove sender/candidate email/body never reach logs; IMAP exceptions are swallowed to fixed codes (`test_imap_errors_are_safe...` injects secrets into an exception and confirms only `IMAP_READ_FAILED` surfaces). `from_email`/`subject` persisted in `inbound_emails` are operational metadata per spec 02, not candidate PII sources — the receipt deliberately uses the CV-extracted (redaction-local) email, never the `From` header. `/settings/mailbox` is admin/lead-only, returns no host/user/password/body (`must-not-return` test), and degrades safely on Redis failure. Attachments go through the T07 magic-byte/macro validator and `MAX_FILES`; filenames are path-stripped (`PurePosixPath(...).name`, backslash-normalized) and printable-filtered.

**Database:** Migration `0007` adds `inbound_emails` (RecordMixin + soft-delete, CHECK on status/attachment_count, unique `message_id`) and `cv_files.source` NOT NULL reusing the existing `candidate_source` enum with `server_default='upload'`; downgrade drops both and is exercised by `test_database.py`.
