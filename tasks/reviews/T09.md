**Findings:**
- [MINOR] F1 — `backend/app/ai/schemas.py`: the generated JSON Schema emits `pattern` (`Text`, `Month`), `minimum` (`years_experience`), and `minItems`/`maxItems` (`reasons`). These are sent verbatim as OpenAI `response_format.json_schema` (strict=true) and Ollama `format`. Some providers' strict structured-output modes have historically rejected these keywords with a 400. The adapter fails safe (returns `LLMError`) and this path is documented NOT TESTED / operator-verified via the smoke script, so it does not block T09 — but the author should confirm OpenAI/Ollama accept these constraints during the first real `--provider openai` / `ollama` smoke, and drop to validator-only enforcement if a provider rejects them. (Anthropic sends `input_schema` without strict validation, so it is unaffected.)
