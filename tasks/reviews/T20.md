## Findings
- **[MINOR] F1 — rejection reason is the i18n display string, implicitly coupled to the backend enum.** `pipeline-board.tsx:166` sends `rejected_reason: t(\`pipeline.reason.${rejectedReason}\`)`, i.e. the literal Vietnamese label (`"thiếu kỹ năng"`, …). That value must byte-match `RejectedReason` in `backend/app/schemas/pipeline.py:15`. It is correct today and pinned by the test at `pipeline-board.test.tsx:231`, but a translator editing the display label in `vi.ts` (e.g. capitalizing) would silently 422 every rejection with no type-level signal. This is inherited from T19's contract (the enum values *are* Vietnamese strings), so not a T20 defect. *Fix (follow-up):* add a short comment in `vi.ts` / `pipeline-types.ts` noting these six strings are the API contract value, or map the machine key (`skills`→enum) at one documented boundary.
- **[MINOR] F2 — `notices` toast-id map is only pruned on undo/unmount.** `pipeline-board.tsx:86` keeps a `Map<applicationId, toastId>`; entries are not removed when a toast auto-closes after its 10 s duration, so stale ids accumulate over a long session. Impact is negligible (bounded by distinct applications; stale `toast.dismiss` is a no-op). No action required.
