**Findings:**
- [MINOR] F1 — `backend/app/services/jobs.py:65,120` `options()` and `list_jobs()` gate on `authorize(actor, "jobs.create")`. Functionally correct (both just mean "any active user", and list scope is enforced separately in SQL), but using a `create` permission to authorize a read/list is semantically misleading. Consider a dedicated read action or a comment. No behavior impact.
- [MINOR] F2 — `save_job` calls `embed_job` on every create/edit, so a PATCH that only touches non-text fields (status, deadline, members) still recomputes the embedding and will return 503 `EMBEDDING_UNAVAILABLE` if the embedder is down. This conforms to spec 03 ("Tạo/sửa gọi `embed_job` T11 trước commit"), so it is not a deviation — just a coupling worth noting for T14+ (a status/deadline change shouldn't strictly need the embedder). Covered by `test_embedding_failure_rolls_back_job_and_members`.
- [MINOR] F3 — `response()` (`services/jobs.py:95`) issues two `session.get` + one members query per single-Job response (list view is already batched). Negligible for single-record endpoints; no action needed now.
