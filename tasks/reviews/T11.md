**Findings:**
- [MINOR] F1 — `app/ai/anonymize.py:74-83`: when parsing yields no usable name match, the fallback masks the first 2–6-word alphabetic line as a possible name header. This can over-mask a section/profession header (e.g. "Senior Software Engineer") when the real name wasn't matched. This is an intentional privacy-leaning tradeoff documented in open-questions #46; no change required, but worth revisiting when real-data eval (gated by legal review per project rules) runs.
- [MINOR] F2 — `app/ai/anonymize.py`: anonymization is label/regex heuristic, not NER; unlabeled PII or OCR-mangled fields on real CVs may survive. Scope and limits are explicitly recorded in spec 04 and open-questions #46, and all T11 tests use synthetic data. Acceptable for M1; flag only so it is not mistaken for full PII guarantee before production.
