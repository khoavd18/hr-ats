## Verification notes
- **Privacy/security:** `.ics` carries only round/time/duration/location — no CV, contacts, feedback, or attendees (`calendar_file` uses read-only `_record`). Activity payloads store only `interview_id`/`offer_id`; test asserts no `feedback`/`interviewers` leak into any activity. HR-entered `location_or_link` is rendered as escaped pre-wrapped text, never a navigable link (frontend test injects `<script>` and asserts it is inert). No email on any path (`email_outbox == []`, and frontend test asserts no `*email*` API call). Auth/scope-from-DB/CSRF/Origin covered by `test_scope_for_all_record_endpoints` (admin/lead/recruiter±member, membership revocation, Application-owner-outside-Job) and `test_auth_csrf_and_origin`; hidden/merged/expired covered by `test_hidden_records_are_unavailable`.
- **Human-in-the-loop:** interview results and offer accepted/declined never auto-move or auto-reject; stage only advances on first interview (submitted→interview), offer sent (interview→offer), placement (offer→hired), each via `pipeline.move(commit=False)` in one transaction. Undo moves stage only and keeps business records.
- **DB:** migration `0005_recruitment_records` adds the three tables with FK NO ACTION, all CHECKs (round/duration/result/salary/sent_at coupling/fee/guarantee/status), UNIQUE placement covering soft-deleted rows, and the three required indexes; downgrade + `compare_metadata` clean on the disposable test DB. Model `__table_args__` match the migration exactly.
- **Spec conformance:** DTOs, input limits, status lifecycles (draft→sent→accepted|declined; placement active/left_in_guarantee/completed), `mine`/date-interval `[from,to)` at Vietnam midnight, and `GET /applications/{id}` ordering (interviews scheduled_at/id asc, offers created_at desc/id, placement-or-null) all match `docs/specs/03` §Contract T21.
- **i18n:** all new strings in `frontend/src/i18n/vi.ts`, Vietnamese, no technical terms ("LLM"/"embedding"/"prompt"/"JSON"); `.ics` surfaced as "Tải tệp lịch"; undo toast + in-drawer undo button present.
- **Seed:** `seed_recruitment` runs only inside the initial-history guard (`StageEvent is None`), so re-running seed adds no duplicate records and never overwrites HR edits; `test_seed_demo` asserts exactly 5 interviews / 10 offers / 5 placements and preserves prior state across a second run.
