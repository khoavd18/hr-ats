## Findings

- **[BLOCKER] F1 — `backend/tests/api/test_export.py:12`: test uses an undefined `records` fixture → errors at setup, never runs.**
  `records` is not a shared fixture in `tests/conftest.py`; it is defined *locally* inside each test module that uses it (e.g. `tests/api/test_jobs.py:30 def records(...)`, `tests/api/test_profile.py:30`). `test_export.py` defines no such fixture, and the one it would need has a different shape (`records.candidate`, `records.job`). Result: `ERROR ... fixture 'records' not found`. Because this is the only backend test for T17, acceptance criteria 1 and 2 are entirely unproven.
  Fix: add a local `records` fixture to `test_export.py` that creates a `HiringUnit`, a `Job` (owned by `account`), and an eligible `Candidate`, returning a `SimpleNamespace(job=..., candidate=...)` — mirroring the pattern in `test_profile.py` — then re-run `uv run pytest tests/api/test_export.py`.

- **[BLOCKER] F2 — `backend/tests/api/test_export.py:62`: phone assertion is inconsistent with the code; test would fail even with F1 fixed.**
  `_excel_text("+84900000000")` returns `"'+84900000000"` (apostrophe prefix, since `+` is a formula-trigger char), and openpyxl preserves that leading apostrophe on read (verified by isolated round-trip). The test asserts `rows[1][1:5] == (..., "+84900000000", ...)` without the apostrophe, so it will fail. Note this is self-contradictory with the full_name assertion at line 59, which *does* expect the preserved leading apostrophe.
  Fix: assert the phone as `"'+84900000000"` (consistent with the formula-safety behaviour the spec mandates), or change the test phone to a value that does not start with `= + - @`. Do not weaken the formula-injection defense in `export.py`.

- **[MAJOR] F3 — Frontend lint gate is red.** `npm run lint` runs `eslint . && prettier --check .`; prettier flags `frontend/src/components/job-detail.tsx` and `job-detail.test.tsx`. DoD requires lint clean. Fix: `npx prettier --write` on both files (and keep the resulting formatting).

- **[MINOR] F4 — Phone/`+`-prefixed values render with a visible leading apostrophe in Excel.** `_excel_text` correctly guards against formula injection, but since openpyxl does not set `quotePrefix`, a phone like `+84900000000` displays literally as `'+84900000000` in Excel. This is a defensible safety/UX trade-off and matches the spec intent (text-safe cells), so it is not blocking — but if a cleaner display is wanted, set the cell value plus `cell.quotePrefix = True` (or restrict the prefix to `= + - @ |` only when Excel would treat it as a formula). Note for the author; no change required for approval.
