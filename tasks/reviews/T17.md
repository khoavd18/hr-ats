## Findings
None blocking.

- **[MINOR] F1 (carryover of prior F4) — `+`-prefixed values show a literal leading apostrophe in Excel.** `export.py:52 _excel_text` prefixes `'` for strings starting with `= + - @` to block formula injection; openpyxl does not set `quotePrefix`, so a phone like `+84900000000` displays as `'+84900000000`. This is a defensible safety/UX trade-off matching the spec's "ghi dạng text" requirement and is accepted; no change required. If cleaner display is ever wanted, set the value plus `cell.quotePrefix = True`.
- **[MINOR] F2 — Slug logic is duplicated in `job-detail.tsx` and `export.py`.** The download is a blob, and the `api` client (`src/lib/api.ts:170`) returns only the body, so the frontend cannot read the server's `Content-Disposition` filename and must recompute the slug client-side. Both implementations strip non-ASCII and produce the same name for the test cases; this mirrors the established T07 download pattern. Acceptable; noted only so the two slug functions are kept in sync if either changes.
